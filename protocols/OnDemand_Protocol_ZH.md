# FedBCert 按需授权聚合：预执行应用回放协议与解释边界

日期：2026-10-15。

本说明对应 configs/fedbcert_on_demand_20261015.json、scripts/run_fedbcert_on_demand_20261015.py 及其服务接口。它记录本次预先确定的工程问题和审阅边界，不报告回放已经完成或门槛已经通过。

## 1. 先冻结协议，再运行成本回放

本次使用已完成 E28b 实验的图、测试节点和已选定模型，不训练、不重新选检查点、不修改系数或接受阈值。旧 E28b 的效用、敏感性和认证结果已经被观察过；本次是这些历史冻结工件上的新增回顾性应用分析，不是新的独立确认，也不是此前未接触测试集上的应用效益检验。

执行顺序必须是：

1. 完成只读输入审计，核对原图、数据划分、检查点、历史预测和协议哈希。
2. 在尚未运行本次成本回放前，使用 prepare 创建独占的 freeze_manifest.json，固定本次配置、输入、实现和环境。
3. 冻结后才运行 run；执行前后均核对冻结文件和模型状态。
4. 完成固定矩阵后才运行分析。不根据部分结果替换图、种子、工作点、策略或阈值。

已有运行目录不能被静默覆盖或恢复，失败记录保留。配置或实现确有缺陷时，应记录原因并创建明确区分的新版本，而不是在旧冻结记录下修改程序后重跑。普通代码单元测试用于实现核查，不作为应用门槛通过的结果；不得先观察正式成本结果再宣称协议已提前冻结。

## 2. 场景：按需获得授权信息，而非永久不可访问

核心 FedBCert 认证策略只读取客户端本地视图以及所请求的有效结构摘要。新增的应用场景另外假设：当本地信息无法证明类别稳定时，存在可按需授权的所有者侧精确聚合服务。

因此，远端信息不是在任何情况下都永远不可访问。认证阶段不读取远端原始特征或端点列表；精确回退通过授权服务获得所需的跨域聚合消息。单进程服务在内部保存各所有者的输入与拓扑，用以模拟这些请求；这不是已经部署的分布式隐私协议，也不证明服务具有生产级访问控制或隔离能力。

本次验证的是：相对于每个目标都使用同一完整图模型的方案，先认证再回退是否能在保持类别输出一致的同时减少所定义的应用层载荷。它不是联邦训练加速，也不证明可以跳过客户端训练或上传，更不证明完整图预测必然比本地预测准确。

## 3. 精确算术下的类别保真命题

固定模型 Theta、局部诱导图、实际完整图 G*、节点特征及预处理。所有对象属于同一版本快照，且 G* 与远端隐藏表示满足当前认证补全集的前提。对目标节点 v，设其本地预测类别为 a_v。

混合策略在认证成功时输出 a_v；未获证书时，通过授权回退精确计算同一 Theta 在 G* 上的类别。若回退与参照使用同一确定性 argmax 平局规则，则

$$
\widehat y_{\rm hybrid}(v)
=\widehat y_{\Theta,G^\star}(v)
\quad\text{对全部被评估目标成立。}
$$

证明分两种情况。已认证时，原定理已覆盖 G* 这个允许实例，所以本地类别等于完整图类别；未获证书时，按定义使用该完整图类别。两种情况覆盖目标集合。

该命题只保类别，不保整个 logit 向量、softmax、排序、校准或真实标签正确性。认证成功不代表业务风险已解决。授权服务不可用、快照变化、计数上界失效或表示域前提不成立时，不能沿用该结论。

在一般部署中，未决或证书不可用的节点只有在精确回退成功后才能保持此输出保真。本次 pilot 的不支持契约、非有限值及完整性错误属于硬停止条件，不通过将异常伪装为认证成功来完成矩阵。

## 4. 固定模型、样本和五种策略

只使用 E28b 原开发阶段选定的主要单元 h=0.9、rho=0.4，以及整图种子 28101–28108。每图固定 6,000 个节点、三个客户端和同一个已保存的 observed-P 模型。模型有 8,775 个可训练参数、64 维隐藏表示、K=3、alpha=0.25。本次没有新训练。

主要负载是原 test_sealed 集合的全部 2,400 个节点。次要负载是同一测试集合中的固定 32 节点：使用 numpy.default_rng(28615+图种子) 无放回抽取位置并排序。该抽样在预测、标签、认证结果及成本之外定义；所有策略和重复共享相同目标。不能用次要负载替换主要负载的判定。

五种策略均使用相同精确回退引擎、批处理、编码和字节计费规则：

| 策略 | 本地直接输出条件 | 摘要输入 |
| --- | --- | --- |
| full_reference | 无，全部目标精确回退 | 无 |
| exposure_only | 目标不在潜在结构暴露范围内 | 比特打包的边界存在性 |
| ball_pairwise | 原欧氏单位球类别差证书通过 | 每个所涉客户端全部本地行的 uint32 计数上界 |
| nonnegative_diameter | 非负域直径感知对称证书通过 | 同上 |
| cone | 非负区间证书通过 | 同上 |

full_reference 对选定目标执行完整图模型的按需精确计算，并非为了构造基线而强制每次计算全部 6,000 个节点的 logits。它不先运行本地 nominal，也不支付其不需要的计数上界费用。这使基线不会因额外收费或免费赠送预计算而被人为弱化。

exposure_only 不使用类别间隔或精确跨边计数。K 项模型的最大传播幂为 K-1；边界行在一次传播后才影响其自身，所以暴露集合为本地拓扑上距边界行 0 至 K-2 跳的节点。K=3 时是边界节点及其一跳本地邻居，不是两跳邻居；K=1 时暴露集为空。

nonnegative_diameter 与 cone 使用相同非负补全集。前者将原单位球误差半径除以 sqrt(2)，用以区分表示域直径缩小的收益与方向、局部传播区间带来的进一步收紧。历史原对称数字不能直接改名为这条更强基线的结果。

## 5. 精确多跳回退和缓存公平性

K 项预测需要最多 K-1 次完整图传播。回退按目标的传播依赖递归展开，包含远端到远端的依赖，并在使用传播行时采用该节点含自环的完整度数。只补目标的一跳远端表示、却继续使用本地度数或忽略第二次传播，不属于这里的精确回退。

每次策略执行都新建服务和空消息缓存。跨域向量在同一批次内按“来源节点、接收所有者、前序传播阶”去重；同一节点发送到不同接收方或不同阶数仍是不同传输。remote_vectors 因而不是独立远端节点总数。

门控策略允许复用它在本次已实际计算的所有者本地编码 H 和不变特征 logits；这些计算已包含在总计时中。不能免费复用完整图传播结果或完整图 logits。full_reference 没有先运行 nominal，不被赠送这类本地缓存，也不被强迫支付不需要的本地整图前向。

独立中心化完整图前向只用于计时区间外的结果核查，其输出不能进入策略选择、依赖规划或回退缓存。服务索引、模型/数据快照准备和当前实现的检查成本仍计入每次策略总时间。所有者侧拓扑存储是本次受控服务的输入前提；本回放没有测量现实中最初建立跨机构拓扑存储的成本。

## 6. 字节、消息、计算时间分开记账

主要指标为总序列化应用层载荷：

$$
\mathrm{total\_wire\_bytes}
=\mathrm{metadata\_wire\_bytes}
+\mathrm{aggregate\_request\_bytes}
+\mathrm{aggregate\_response\_bytes}.
$$

字节数来自实际生成并解码的二进制请求/响应，而不是只用向量个数估算。应用层记录包括快照头、协议字段、所有者和传播阶、节点 ID，以及相应数值。聚合数值使用 float64；计数摘要使用 uint32，存在性摘要使用比特打包。即使服务返回恰好精确的计数，认证仍解释为真实计数不超过该值，而不是等式约束。

这里的 wire 是应用协议记录名称，不等于真实链路流量。它不包括 TCP/TLS、重传、握手、真实访问审批、隐私管理或人工核查成本。元数据中的来源与快照字段也不能自行证明现实计数完整或真实。

当前 runner 的 request_response_packets 字段累计元数据与精确聚合回退的全部请求/响应应用消息，单次批量 RPC 计两条消息；aggregate_request_response_packets 与 metadata_request_response_packets 分别记录两个分项，总项等于分项之和。报告时应标为“请求/响应应用消息数”，不能将其解释为 TCP/IP 包数或真实网络请求成本。元数据与聚合的请求/响应字节也均计入总载荷。

CPU 回放时间使用单进程 CPU 环境中的墙钟计时，而非网络端到端时延。它包含服务准备、所需本地推断、元数据获取、证书、依赖规划、序列化/解码和精确回退；模型与数据磁盘读取、离线中心参照核查被排除。各分阶段字段用于解释成本，不能保证其和穷尽总时间中的所有控制开销。

不把字节与毫秒直接相加。若另给理想带宽模型，只能明确写出串行计算假设和 bits/bytes 换算，并说明它不是实测网络加速；真实往返延迟、计算通信重叠和安全开销未被测量。

## 7. 计时、统计与自定工程门槛

环境固定为 CPU float64、一个 intra-op 与一个 inter-op 线程、eval/no-grad。每个种子、负载、策略执行一次预热和三次正式重复。策略按“案例索引+负载索引+重复索引”循环轮换；每次执行重置服务和消息缓存。八个种子、两类负载、五种策略、三次正式重复共 240 条正式记录；预热不作为统计重复。

先在每个整图种子/负载/策略内取三次 CPU 时间的中位数。字节减幅和时间比先逐种子配对计算，再对八个种子汇总，不能用汇总字节或汇总耗时之比替代。节点、客户端和重复执行不当作独立样本。10,000 次配对整图种子自助抽样使用随机种子 28616；区间只是八个历史种子的描述性区间，不是新的确认性显著性声明。

对主要 2,400 节点负载，cone 的工程门槛为：

1. 全部输出类别零不一致，且输入、模型、冻结记录和数值核查全部通过。
2. 相对 exposure_only 的逐种子平均总载荷减幅至少 5%，并且至少 6/8 个种子为正。
3. 相对 nonnegative_diameter 的平均总载荷减幅严格为正。
4. 相对 full_reference 的平均总载荷减幅严格为正。

这些数值是本次自行制定的 pilot 工程可行性门槛，不是理论常数、假设检验显著性标准、现实成本节省标准或期刊接收标准。门槛不要求 CPU、载荷、消息数及所有次要指标同时下降。可能出现减少载荷但总 CPU 时间增加，必须同时报告。

若主要门槛未通过，保留负结果并停止扩大应用主张，维持认证方法论文定位；不改用另一个单元、种子、工作负载或事后阈值取得通过结果。即使通过，也只支持该受控按需服务场景，不能升级为工业部署效益。

## 8. 浮点边界与停止条件

类别必须与同一中心完整图参照的 argmax 完全一致，不给类别翻转设置容差；平局统一取第一个索引。精确回退 logits 与参照的绝对误差不超过 1e-10；历史本地输出、证书掩码和模型状态也须核对。

默认认证接受 guard 为 1e-6，支配关系数值核查容差为 1e-10。这些不是向外舍入误差界，也不使有限回放变成严格机器级证明。近零间隔、不同稀疏求和顺序和不同批大小可能产生数值差异，不能通过忽略节点、改类别或扩大容差隐藏。

类别不一致、非有限输出、输入/模型/实现哈希变化、不支持的契约及超出预定总运行时间均须停止并保留失败记录。全部回放零不一致只能支持当前指定快照上的实现一致性；数学上对所有允许补全的保证仍来自精确算术定理及其前提。

审阅时的 runner 符合以下控制边界：routing 不读取标签或中心参照预测；full_reference 无计数请求及 nominal 前向；门控的本地前向和实际缓存复用计时；中心参照仅作独立审计；各策略共享精确回退与序列化引擎。服务实现按需构造多阶依赖，没有将中心完整图传播或 logits 作为免费缓存交给回退。
