# RG-1.0 runner

This is the fixed Cora/CiteSeer joint protocol, not a model-selection tool.
The implementation does not change FedBCert's mathematical certificate.
All statements about floating-point results remain implementation checks,
not outward-rounded numerical proofs.

Use the independent Python 3.9.25 environment at
`environments/FedBCert_RG1_20261020/bin/python` in the parent project.
It uses the retained PyTorch 2.8.0+cpu wheels and pinned dependencies; it does
not inherit system site-packages. Training and evaluation are frozen to CPU,
one intra/inter-op thread, with no automatic device fallback. Dependency pins,
wheel SHA256 values, the pip installation report and import-path checks are in
`results_boundary_certified/fedbcert_rg1_runner_preparation_20261020/`.

## Commands and phase boundaries

Run the following from this source worktree; every output path must be new:

```sh
PY=/absolute/project/environments/FedBCert_RG1_20261020/bin/python
$PY -B scripts/run_fedbcert_rg1.py dry-run --out /new/engineering-output
$PY -B scripts/run_fedbcert_rg1.py prepare --out /new/prepared-inputs
```

`dry-run` uses engineering seed 42020000 and generated toy data only. It runs
the complete paired training/sealing/evaluation path twice. Toy dimensions and
two training rounds are explicitly marked engineering-only. Time measurements
are retained but are not treated as deterministic tensor outputs.

`prepare` validates the pinned standard-data files, dimensions and tensor
hashes from the prior preflight; it does not make real-graph predictions. It
saves local-only train/validation capabilities, separate evaluation vaults,
96 random initial states, and a complete immutable manifest. The 96 planned
models always have the registered 100 rounds and fixed optimization settings.

Formal commands exist for later author-approved execution, but are not run by
either command above:

```sh
$PY -B scripts/run_fedbcert_rg1.py train --manifest /prepared/frozen_inputs/manifest.json \
    --out /new/approved-execution --authorization /author/approval.json
$PY -B scripts/run_fedbcert_rg1.py evaluate --manifest /prepared/frozen_inputs/manifest.json \
    --out /new/approved-execution --authorization /author/approval.json
```

No formal approval file is generated by this implementation. The author must
explicitly bind `approved: true`, `manifest_sha256`, `output_directory` (absolute
and exact), and `scopes` (`train` and/or `evaluate`). Missing, false or mismatched
approval is rejected. Evaluation additionally requires a verified all-model
seal. This is a workflow gate in a trusted local environment, not a security
boundary against a user who can rewrite Python code.

## Training and retained evidence

- The training API accepts only local features/edges and masked train and
  validation target vectors. It has no test-label or full-graph parameter.
- P/I share initialization and per-round/client RNG streams. I uses identity
  propagation during training, validation and evaluation; the independent MLP
  ignores graph propagation.
- Clients reset Adam each round; all three clients participate. FedAvg weights
  are labelled training counts. Validation Macro-F1 selects each model's own
  checkpoint; exact ties select the earliest round.
- Initial, selected and final states, every round's validation evidence, the
  combined trajectory and hashes are retained. Interrupted models retain a
  partial state and failure reason; they cannot receive a completion seal.
- The full planned matrix, input hashes, source hashes and selected model
  artifacts are verified before any evaluation vault is deserialized.

## Evaluation and accounting

L receives the local induced graph and never creates a remote service. F/E/S/D/N
reuse the existing owner-side replay codec, batching, cache scope and exact
dependency engine. Full-graph reference logits are offline checks, never cache
inputs. I/MLP controls have zero remote payload and use identity propagation.
Each strategy has one warmup and three measured empty-cache runs on both
workloads. The six P strategies rotate by case, workload and repetition index.

The main CPU field is single-thread `perf_counter` replay time; process CPU time
is auxiliary. Snapshot checks and required setup are timed. Disk loads and
offline reference checks are excluded. Header/ID, summary and vector bytes are
serialized and decoded by the existing implementation, not estimated.

All three certificates use the same P checkpoint and logits. Per-class margin
and per-order representation diagnostics, class-flip checks and certificate
hierarchy checks are saved. There is no positive-effect early stopping rule.
Missing or zero-denominator ratios remain NA in the paired descriptive analysis.

The supervisor enforces phase/per-model/per-record deadlines, sampled worker
process-tree RSS and combined input/output storage budgets. Completed files use
exclusive atomic publication. Failed runs remain present; there is no automatic
resume, retry, smaller budget, seed replacement or GPU/CPU switching.

Tests are in `tests/test_fedbcert_rg1_*.py`. They use toys and mock resource-limit
violations; no formal real-graph training or evaluation is required to run them.
